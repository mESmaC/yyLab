This archive preserves the completed bounded allocator experiment round. It contains exact copies of the wrappers, serial runners, seven standard-library hook tests, saved recipes, the two early failure reports, both stopped retry receipts/logs/interventions, and the unfinished B128 report. `manifest.json` records every file's SHA-256, original restoration path, dependency hash, validation scope, and the status snapshot.

The base wrapper sets the native CUDA allocator policy before Torch imports. It can release unused reserved memory once after the first warmup update or once after all warmup; those choices are mutually exclusive. Release synchronization and `empty_cache` occur outside measured training steps and have separate timing/memory attestations. First-step release remains included in the harness's total `warmup_and_compile_seconds`. Peak memory counters still include startup and warmup. These experiments do not establish that allocator reservations caused any earlier performance collapse.

The initial first-step attempts at effective batches 32 and 128 failed before training because the allocator fraction query received `torch.device('cuda')` without an explicit index. Their exact source is `benchmark_allocator-before-device-index.py`; the fixed current wrapper and the unmeasured older pre-first-step snapshot are preserved separately. The B32 retry was stopped after 413.68 seconds without a completed training throughput result; its intervention recorded 1,933,574,144 bytes of shared GPU memory. No rate is accepted from that attempt. The B128 retry was stopped after 232.44 seconds without a completed timing; its intervention recorded 1,839,202,304 bytes of shared GPU memory. Its unfinished report still says `running` and contains zero cases; the final process/intervention receipts establish that it was stopped. All allocator GPU jobs have ended. Neither retry produced an accepted throughput rate.

`benchmark_allocator_bf16.py` and its runner compose the allocator observer with the separately archived, explicitly named BF16-moment optimizer candidate. That candidate changes optimizer numerics: large compiled slices store moments in BF16, native tails retain FP32 moments, and masters/update arithmetic remain FP32. It has no production checkpoint/resume contract or convergence claim. Both combined recipes were prepared and dry-run validated but were not executed in this round. The GC/fraction-cap and post-warmup-only release recipes were also not executed. The complete BF16 candidate source is one directory above this archive; its exact hash and restoration path are in the manifest.

Seven standard-library tests passed before archiving. They use fake Torch/engine/harness objects and the actual candidate context extracted as AST to check release ordering, metadata/source attestation, and hook restoration on failures. They do not validate GPU allocator performance or numerical training behavior. No production source was changed for these experiments.

To reproduce, first restore files and the dependency to their `original_path` locations in a disposable checkout. These scripts assume that directory depth and must not be run directly from this documentation folder. Use a fresh output directory; both serial runners refuse existing outputs/logs/receipts/locks. Run `test_allocator_wrappers.py` for the standard-library checks, or the appropriate serial runner with saved recipe names and `--dry-run` for admission checks. Omit `--dry-run` only when intentionally scheduling a GPU experiment. Existing historical output directories must remain untouched.
